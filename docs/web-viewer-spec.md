# 全天球ビューア Webコンテンツ 仕様

最終更新: 2026-07-27

## 目的

`allsky_surveys.py` / `download_allsky_fits.py` / `convert_allsky_png.py` で生成した
全天球サーベイ(電波・赤外線・可視光・紫外線・X線・ガンマ線 + Gaia DR3カラー)を、
球体テクスチャとして貼り付け、内部(球の中心)から見る形で表示するWebコンテンツ。

スマートフォンの位置情報とジャイロ/コンパスを使い、実際の空と同じ方向に
該当サーベイの見え方を重ねて表示する機能も実装済み(`viewer/src/skyLock.ts`)。

`viewer/`ディレクトリに実装済み。詳細は[`../viewer/README.md`](../viewer/README.md)、
全体構成は[`system-architecture.md`](./system-architecture.md)を参照。

## 確定した方針

| 項目 | 決定事項 |
|---|---|
| レンダリングライブラリ | Three.js(TypeScript) |
| データ形式 | **PNG**(convert_allsky_png.pyが生成する事前stretch済み8bitグレースケール)。当初はFITSをそのまま渡す設計だったが、デプロイ時のペイロード(FITS合計約800〜900MB)が大きすぎるため方針転換した(2026-07-27)。詳細は下記「方針転換の経緯」参照 |
| インタラクティブ操作範囲 | 疑似カラーLUT(colormap)の選択と、2サーベイ間のクロスフェード切り替えのみ。stretch方式/strength/percentileはPNG生成時に焼き込み済みでクライアント側では変更不可 |
| サーベイ切り替え/ブレンド | 2サーベイ間のクロスフェードスライダー(例: 電波↔可視光)。3枚以上の同時レイヤー合成は対象外 |
| ホスティング形態 | 完全な静的サイト(サーバー/APIなし。GitHub Pages等を想定) |
| 読み込みタイミング | 全サーベイ(8ファイル)を起動時に一括プリロード |
| データ総量 | PNG化により合計約130MB(旧FITS方式の800〜900MBから大幅削減) |
| 対応ブラウザ | WebGL2対応のモダンブラウザのみを想定。WebGL1フォールバックは作らない |
| UIの作り込み | 最小限のデバッグUI(プレーンなHTMLスライダー/セレクトボックス程度) |
| 位置情報・傾き連動 | 実装済み。Geolocation + DeviceOrientationから計算したAlt/Az→赤道座標→銀河座標→ワールド方向でカメラを固定 |

## 方針転換の経緯: FITS直読み → PNG読み込み

当初は「配色やasinhなどをインタラクティブに変更できるように」という要件から、
FITSをそのままブラウザに渡しクライアント側でstretch計算する設計を採用し、
実装・動作確認まで完了していた(FITSパーサー、ヒストグラム近似percentile、
GPUシェーダーでのstretch適用など)。

しかしGitHub Pagesでのデプロイを検討した際、以下の制約が判明した:
- GitHubは1ファイル100MB超のpushにGit LFSを要求するが、scalarサーベイのFITSは
  1ファイル約128〜268MBで抵触する
- Git LFSを使ってもGitHub PagesはLFS実体を配信しない(ポインタファイルが返る)
- 仮に解決してもGitHub Pagesの帯域目安(月100GB程度)を、起動時800〜900MB
  プリロードの設計では数百アクセスで使い切ってしまう

この3点を踏まえ、「配色(colormap)は保つが、stretchのインタラクティブ性は失う」
トレードオフを許容し、事前stretch済み8bit PNG(合計約130MB)を読み込む方式に
変更した。FITS直読み用のコード(`fitsLoader.ts`, `percentile.ts`)は削除済み。

## 未確定・次の検討事項

- Gaia DR3カラーサーベイ(`02b_visible_gaia_dr3_color`)はまだダウンロード・PNG変換されていない。
- PNGアセット(合計約130MB)の静的ホスティング先(GitHub Pages / 他CDN等)と配置方法は未定。
- コンパス方位・高度角の符号は実機テストでのみ最終確認可能(`viewer/README.md`参照)。

## 実装優先順位(実施済み)

1. Three.jsで球体(内部から見るスカイボックス構成)の基本表示
2. GPUシェーダーでのcolormap適用 + 2サーベイ間クロスフェード
3. 全サーベイのプリロード
4. デバイス位置情報・傾き連動(実装済み、実機での符号検証が残課題)
